Bức Tranh Tổng Thể Docker

Trước khi có Docker, việc cài đặt code từ máy Dev sang máy Khách hàng là một thảm họa (lỗi thiếu thư viện, sai phiên bản...). Docker sinh ra để giải quyết câu nói kinh điển: "Nhưng mà code chạy bình thường trên máy tôi cơ mà!" bằng cách đóng gói TẤT CẢ (code, môi trường, thư viện) vào một cái hộp tiêu chuẩn.

Vòng đời của một ứng dụng Docker

Phần 2

Các lệnh cốt lõi (Vận hành)

💿

Quản lý Image (Khuôn đúc)

docker pull <tên_image> Tải một image từ Docker Hub về máy.
docker images Xem danh sách các image đang có trong máy tính.
docker rmi <image_id> Xóa một image (chỉ xóa được khi không có container nào đang dùng nó).
📦

Quản lý Container (Thực thi)

docker run -d -p 8080:80 --name my-web nginx

Câu lệnh dùng nhiều nhất: Khởi tạo và chạy 1 container.
-d: Chạy ngầm (không chiếm terminal).
-p 8080:80: Nối cổng 8080 của máy bạn vào cổng 80 của Container.
--name: Đặt tên cho dễ nhớ.

docker ps Xem các container đang chạy. (Thêm -a để xem cả container đã tắt).
docker stop <tên_hoặc_id> Dừng một container đang chạy.
docker start <tên_hoặc_id> Bật lại một container đã dừng.
docker rm <tên_hoặc_id> Xóa hẳn container (Phải stop trước khi xóa, hoặc dùng -f để ép xóa).
🩺

Gỡ lỗi (Debugging)

docker logs -f <tên_container> Xem luồng log in ra màn hình của app (thêm `-f` để xem trực tiếp theo thời gian thực).
docker inspect <tên_container> Xem toàn bộ thông tin chi tiết (địa chỉ IP, biến môi trường, Volume) của container.
docker system prune -a Dọn rác! Xóa tất cả các container đã tắt và image không dùng (Giải phóng ổ cứng).
🚪

Chui vào Container & Copy File

docker exec -it <tên_container> /bin/bash

"Chui" vào container: Mở terminal trực tiếp bên trong container đang chạy. (Nếu báo lỗi không tìm thấy bash, hãy đổi thành sh).

docker exec <tên_container> node app.js Thực thi một câu lệnh bên trong container mà không cần chui vào.
docker cp data.txt <tên_container>:/app/ Copy file từ máy tính ngoài vào trong container.
docker cp <tên_container>:/var/log/error.log ./ Lấy (copy) file từ trong container ra ngoài máy tính của bạn.
Phần 3

Bí Kíp Viết Dockerfile

Dockerfile chính là "công thức nấu ăn". Nó chứa từng bước hướng dẫn cho máy tính biết làm thế nào để cài đặt môi trường và copy code của bạn vào thành 1 cái Image.

📄 Dockerfile (Ví dụ chạy app NodeJS) Copy 
FROM node:18-alpine
# Bắt buộc phải có. Lấy hệ điều hành nền có sẵn NodeJS 18. (Dùng bản alpine cho nhẹ)

WORKDIR /app
# Tạo một thư mục tên là /app bên trong container và đi vào đó (như lệnh cd)

COPY package*.json ./
# Copy file mô tả thư viện từ máy tính của bạn vào thư mục /app hiện tại

RUN npm install
# Chạy lệnh cài đặt thư viện (lệnh này chạy TRONG LÚC build image)

COPY . .
# Copy toàn bộ code còn lại vào container

EXPOSE 3000
# Khai báo cho người dùng biết app này sẽ chạy ở cổng 3000

CMD ["npm", "start"]
# Lệnh CUỐI CÙNG. Sẽ được thực thi khi bạn gõ "docker run..." (Khởi động app)

🚀 Quy trình Build và Đẩy Image lên Registry (Docker Hub / GitLab)

Bước 1: Đăng nhập vào Registry

docker login Đăng nhập vào Docker Hub (mặc định). Nếu dùng GitLab, gõ: docker login registry.gitlab.com

Bước 2: Đóng gói & Gắn thẻ (Build & Tag)

docker build -t ten_username_cua_ban/ten_app:v1 . Lưu ý dấu chấm . ở cuối nghĩa là đọc file Dockerfile tại thư mục hiện tại. Cấu trúc Tag chuẩn: <tên_tài_khoản> / <tên_ứng_dụng> : <phiên_bản>.

Bước 3: Đẩy lên kho (Push)

docker push ten_username_cua_ban/ten_app:v1 Gửi Image lên mạng. Sau bước này, bạn có thể sang máy chủ khác và gõ docker pull ... để tải ứng dụng về chạy.
Phần 4

Docker Compose (Nhạc trưởng)

Nếu ứng dụng của bạn chỉ có 1 container (chỉ có Code) thì chạy `docker run` là xong. Nhưng nếu bạn cần chạy cả Code, Database (MySQL) và Cache (Redis) cùng lúc thì sao? Thay vì gõ 3 lần lệnh `run` lằng nhằng, ta dùng docker-compose.yaml.

📄 docker-compose.yaml (App kết nối MySQL) Copy 
version: '3.8'

services:
  web-app:                  # Tên container ứng dụng
    build: .                # Bảo compose tự đọc Dockerfile ở thư mục hiện tại để build
    ports:
      - "3000:3000"         # Mở cổng ra ngoài
    depends_on:
      - db                  # Đợi database chạy xong thì mới chạy app này

  db:                       # Tên container database
    image: mysql:8.0        # Dùng image mysql có sẵn trên mạng
    environment:            # Truyền biến môi trường để cấu hình MySQL
      MYSQL_ROOT_PASSWORD: root_pass
      MYSQL_DATABASE: my_db
    volumes:
      - db_data:/var/lib/mysql  # Gắn ổ cứng ảo để không mất data khi tắt container

volumes:
  db_data:                  # Khai báo tạo ổ cứng ảo
docker-compose up -d

Khởi động toàn bộ hệ thống các container được định nghĩa trong file. -d để chạy ngầm.

docker-compose down

Tắt và dọn dẹp sạch sẽ toàn bộ các container và mạng lưới liên quan (data trong volume không bị mất).

Phần 5

Ổ cứng (Volume) & Mạng lưới (Network)

💾 Lưu Trữ (Volume)

Mặc định, xóa container là mất dữ liệu. Volume giúp lưu dữ liệu ra ngoài container để dùng lại.

  • docker volume create my-vol Tạo 1 ổ cứng ảo.
  • docker run -v my-vol:/data nginx Gắn ổ `my-vol` vào thư mục `/data` bên trong container nginx.

🌐 Mạng Lưới (Network)

Giúp các container độc lập có thể "nhìn thấy" và giao tiếp với nhau bằng tên.

  • docker network create my-net Tạo 1 mạng nội bộ ảo.
  • docker run --network my-net ... Cho container tham gia vào mạng đó.
Phần 6

Nginx Thực Chiến (Cấu hình default.conf)

Khi bạn mua một tên miền (vd: botkeep.cloud) và muốn trỏ nó vào container NodeJS (đang chạy ở cổng 3000), bạn không thể bắt khách hàng gõ botkeep.cloud:3000 được. Bạn cần một Nginx Container đứng ở cửa (cổng 80) để nhận luồng truy cập và dẫn đường (Proxy) vào bên trong.

📄 default.conf (File cấu hình Nginx) Copy 
server {
    listen       80;
    # Lắng nghe các truy cập vào cổng 80 (cổng web mặc định)

    server_name  botkeep.cloud www.botkeep.cloud;
    # Tên miền của bạn. Nginx sẽ kiểm tra xem khách truy cập domain nào để xử lý

    location / {
        proxy_pass http://my-nodejs-app:3000;
        # QUAN TRỌNG: Điều hướng khách hàng tới container có tên "my-nodejs-app" ở cổng 3000
        
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        # Truyền lại IP thật của khách hàng vào cho app NodeJS biết
    }
}

🔌 Cách áp dụng file này vào Container

Bạn tạo file default.conf ở máy tính ngoài, sau đó dùng Volume (trong docker-compose.yaml) để ghi đè nó vào thư mục cấu hình của Nginx bên trong container:

services:
  nginx:
    image: nginx:alpine
    ports:
      - "80:80"
    volumes:
      # Map file của bạn đè lên file mặc định của Nginx
      - ./default.conf:/etc/nginx/conf.d/default.conf
Phần 7

Từ Điển Thuật Ngữ (Phong cách "Ví von")

💿 Image

Ví von: "Khuôn đúc / Đĩa cài game".
Nó chứa hệ điều hành, code và thư viện, ở trạng thái "đóng băng" (Read-only). Bạn không thể thay đổi nội dung của Image sau khi tạo ra.

📦 Container

Ví von: "Sản phẩm đúc ra / Game đang chơi".
Là một phiên bản ĐANG CHẠY của Image. Bạn có thể chui vào nó, tạo file mới, nhưng khi tắt và xóa đi, mọi thứ thay đổi sẽ bay màu. (1 Image có thể đẻ ra hàng trăm Container).

📄 Dockerfile

Ví von: "Bản vẽ kỹ thuật".
Một file text chứa các dòng lệnh (VD: Lấy hđh Ubuntu -> Cài PHP -> Copy code vào). Docker sẽ đọc file này từ trên xuống dưới để tự động đóng gói ra một Image.

☁️ Registry (Docker Hub)

Ví von: "App Store / Google Play".
Nơi chứa các Image. Bạn có thể đẩy Image của bạn lên đây (`docker push`), hoặc tải image của người khác (như image mysql, nginx) về dùng (`docker pull`).

💾 Volume

Ví von: "Ổ cứng cắm ngoài (USB)".
Container rất dễ bị xóa. Bạn cắm Volume vào để lưu trữ Database hoặc file upload. Lần sau bật Container mới, cắm lại USB đó vào, dữ liệu vẫn nguyên vẹn.

⚙️ Docker Daemon

Ví von: "Động cơ xe".
Phần mềm chạy ngầm trong máy tính của bạn. Khi bạn gõ lệnh `docker run` (Bấm ga), Client sẽ gửi lệnh xuống Daemon, và Daemon chính là người thực thi việc tạo mạng, tạo ổ cứng, khởi động container.
